0 The idea in one line / mode: operate · density: high · motion: minimal

Every page is the same vertical stack - story banner, page header, meta line, KPI row, section or table cards, dialogs - and the six archetypes only change which of those blocks a page fills in, never the shell around them.

The three locks hold across all 15 pages: one accent (the existing green, status colors reserved for data states), one radius system (6px cards, 4px small tiles, pills only for badges), and one theme (dark, border-defined elevation, no shadows - the product's existing doctrine).

1 (a) Shared page anatomy / the one skeleton every page uses

The skeleton below is the template rendered with Store Sync's real structure as the example. Numbered parts map to the annotation column. The stack is fixed: the banner is always first, the data table is always the last content block, dialogs float above.

1FeatureStoryBanner

Finalized, untouched. Renders only when a story is passed. PageTemplate guarantees it is always the first block (fixes Store Management / Employee Directory, which currently render it after the header).

2PageHeader (new)

title · subtitle · actions. Display h1, border-b, actions right. Same visual as today's DashboardPageHeader, now part of the template stack.

3MetaLine (new)

items: ReactNode[] rendered as a bullet-separated line. Own component so live values (countdowns, timestamps) re-render without touching the header.

4KpiRow (new)

columns: 2 | 3 | 4. Grid strip whose children are StatCard (ui/cards, the one KPI card; DashboardStatCard is deprecated dead code).

5SectionHeading (new)

Bare h2 + subtitle + actions for unframed content. Replaces raw <h3 class="section-title"> in System Health and restores correct heading levels.

6TableCard (new)

title · subtitle · actions · toolbar · footer. Header with border-b, optional toolbar strip, flush table body. The terminal element of every table page.

7Dialogs

Existing shadcn primitives stay (Dialog, ConfirmDialog, EntityFormDialog). Roles Admin's hand-rolled overlay is replaced by Dialog in the refactor phase.

8Fatal / empty states

Bypass the template: DashboardLayout + EmptyState directly, exactly like today's early returns. The template is for the loaded path only.

9Constrained variant

constrained prop narrows the whole column to max-w-2xl for utility pages (Profile, Logout). Spec'd now, applied later.

Skeleton constants: page padding 32px, section gap 24px, card padding 16px, card radius 6px, table row 48px. All values are the existing tokens (--page-px, --section-gap, --card-p, --rounded-sm) - the template introduces no new dimensions.

2 (b) Six archetypes, one template / the middle blocks vary, the shell never does

Each page picks an archetype and fills its slots. Slots marked with a dashed outline are optional per page. Dialogs float above every flow where the page needs them.

3 (c) Sidebar restructure / proposal only - not implemented in this phase

Today "Tools" is a collapsible nested under Operations (Office Agents / Agent Updater hidden one level deep). Proposal: promote Tools to its own top-level group with flat items. The nav component already supports flat groups, so this is a data-shape change in components/layout/Sidebar.tsx, no component work.

4 (d) Audit findings, before / after / all eight reconcile into the template

F1System Health uses a different shellpages/SystemHealth + shared/PageShell + shared/PageHeader
Before

PageShell + PageHeader instead of DashboardLayout + DashboardPageHeader; raw <h3 class="section-title"> headings; carries a @ts-nocheck.

After

PageTemplate (archetype B), SectionHeading h2 for "Services Status" / "System Logs", TableCard for the logs table. @ts-nocheck removed during the refactor.

F2Banner after header on two pagespages/StoreManagement, pages/IdentityCheck
Before

FeatureStoryBanner renders after DashboardPageHeader, breaking the story-first rhythm every other page uses.

After

PageTemplate hard-codes the order: banner always first, header second. The two pages just stop overriding the sequence.

F3Store Sync table section differspages/StoreSync/index.tsx
Before

Bare BaseSection wraps the table while every other table page uses a card or raw Card; filter controls crammed into the section header row.

After

TableCard with title + toolbar slot: search, branch and status selects move into the toolbar strip, the table sits flush beneath.

F4Roles editor is a hand-rolled overlaypages/RolesAdmin/index.tsx
Before

Fixed-position div overlay: no role="dialog", no focus trap or restore (logged as ui-audit 7c.8).

After

shadcn Dialog (already in the repo): keyboard navigation, focus management, Escape to close. The role cards stay SectionCards in a grid.

F5Backups uses BaseDataTablepages/Backups/index.tsx
Before

Raw BaseDataTable with hand-managed manual pagination; one of two table implementations across pages.

After

Standard DataTable (pagination prop covers manual mode) inside TableCard. One table primitive everywhere.

F6Dead KPI componentscomponents/base/dashboard-layout.tsx
Before

DashboardWelcome and DashboardStatCard unused; two KPI card implementations exist (the live one is ui/cards StatCard).

After

Marked @deprecated in this phase; deleted in the refactor phase. StatCard is the single KPI card, composed via KpiRow.

F7Utility pages constrain themselvespages/Profile, pages/Logout
Before

Each hand-rolls max-w-2xl wrappers; Profile also uses ui/cards SectionCard directly.

After

The constrained prop on PageTemplate encodes the pattern. Utility pages stay untouched this round; the variant is designed and documented.

F8Banner usage is consistentall 15 pages
Before

Already uniform (banner component, story keys, compact button variant) - the good baseline.

After

Kept exactly as is. PageTemplate just slots it in first position and stops pages from mis-ordering it.
